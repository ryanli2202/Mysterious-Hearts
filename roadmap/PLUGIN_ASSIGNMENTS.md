## Assessment

1. **The current order still fits the dependencies.** Interiors establishes rooms, access, presence, outfits and save contracts; MH-016 then supplies Maps travel, gauntlets and scene presentation. Mavis proves the shared Ace foundation before Martos, Elias and Camila; Sylvanis follows them. Story Skills and Writer's Loop can support chronology and manuscripts alongside interiors. Takeo's implementation slot remains unassigned. This review does not resume MH-016 or the paused Rei artwork.
2. **Continuity needs explicit source records before automated checks can help.** Campaign plans contain branch-specific outcomes, concealed identities and separate historical versions. The Story Skills workspace is a starter, not an imported manuscript. Populate only the authorised scope, preserve runtime IDs in source mappings, and manually review branch rejoins and facts the CLI cannot model. A clean empty-workspace check cannot certify game continuity.
3. **Stateful integration is the main verification risk.** Interiors needs co-presence, permission, wardrobe and migration assertions; campaigns need outcome, era, audience, retry and one-time-effect assertions. Assign falsegreen-skill to those substantive tests, then execute the tests and inspect the game. It does not implement features, replace the test runner, or prove rendering quality.
4. **Media plugins cover preparation and motion, with a clear painting gap.** Bulk BG Remove handles needed cutouts; prompt-to-asset handles restricted local SVG/export tasks; DESIGN:OS handles suitable vector motion; Pro Motion handles local compositing and synthetic effects. None of this restricted setup generates the detailed manhwa portraits, room paintings or per-shot scene illustrations. Those remain separate, explicitly scoped artwork production using a permitted workflow. Do not substitute primitive placeholders or unlock a paid provider to fill the gap.
5. **Generated assets still need game integration.** MH-001's produced GIFs, MH-013's staged wardrobes and interiors batch 01 retain their distinct production/integration status. HTML/SVG/MP4 previews need a verified Tk-compatible asset or implementation path. Validate alpha, timing, dimensions, scaling and cancellation in the actual renderer; local video success is not gameplay success.
6. **Sound and trailers are conditional.** No current plan requires a new trailer or general audio redesign. Pro Motion and SFXMint have explicit conditional cue assignments; launch-film is reserved for a requested trailer/launch deliverable. All ten plugins have a route, but unrelated tools are not mandatory steps in every update.
7. **Historical records remain historical.** Released plans receive future-maintenance assignments only. Earlier status/evidence paragraphs are retained with their dates; current status fields and later completion records govern. The existing duplicate MH-004 labels (Lived-In Interiors and released Narrated actions) are preserved, not renumbered; use title and document link to disambiguate. New entries use the next unused ID.

## Execution and future plans

For every new or materially revised update, use [UPDATE_TEMPLATE.md](UPDATE_TEMPLATE.md). Break milestones into concrete tasks and assign relevant plugins before execution, including in each separately maintained child plan. Identify the deliverable, verification, dependency/pause gate and status of each assignment. Use **Required when task runs**, **Conditional — name the trigger**, **Future maintenance only**, or **Not applicable — give the reason**. Do not insert unrelated art, audio or trailers just to use every plugin.

Use Codex's ordinary implementation tools for Python/Tk gameplay, saves, permissions and integration where no plugin fits. Plugins assist the stated tasks; they do not own game mechanics or replace engineering judgement. Existing authorisation carries across workflows; new material decisions and genuinely expanded scope still need the user.

For combined authorised media tasks, record the actual sequence: source/brief → local SVG/export or necessary cutout → suitable vector animation/compositing → optional requested trailer assembly → game/file verification. Run prepared launchers yourself. Read only the skills needed for the current execution step; resolve pinned paths through the lock. Do not run global installers, provider setup, paid downloads or publication workflows.

Keep draft media in `media-workspace/` and installation fixtures in `.test-tmp/media/`. Check applicable licences and preserve source files, generation/synthesis provenance and hashes. For any new sound, record stable source page (or local synthesis source), licence, AI/synthesis origin, original/processed SHA-256 and recipe in `SOUNDS.md`; use `sound.py`, preserve mute/volume, and preview in context. File measurements alone do not establish listening suitability.

After changing structured Story Skills records, run `tools/story.ps1 reindex`, `wordcount --write`, then `check` against `writing/story-skills`, as documented in the source map. Review path/knowledge limitations and run game tests separately. This assignment pass changes no structured story records, so it does not run or claim a continuity check.

All physical activity remains in person. Changed phone surfaces require existing dark theme/dialog wrappers, popup/scrollbar/control states, `tests/phone_dark_theme_smoke.py`, relevant feature smokes and rendered inspection. Record actual commands, outputs, test counts, screenshots/listening findings and unresolved limitations with the task. Keep **assigned**, **executed**, **verified** and **released** distinct. Player-visible changes still require accurate catalogue entries, validation and export; planning alone does not become a Release.
